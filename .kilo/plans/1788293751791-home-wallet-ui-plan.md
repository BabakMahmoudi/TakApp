# Home + Wallet UI Rework Plan

## Goal

Restructure the logged-in home dashboard and add a dedicated Wallet page:

1. Home panel shows only **TAK balance in large font** at the top, with the **address** underneath (no XLM, no full balance list).
2. New **Wallet page** shows **both XLM and TAK balances** plus **Get TAK** and **Send** buttons.
3. Remove **Profile** and **Admin Panel** buttons from the home grid (they remain reachable via the nav menu).
4. Home action grid becomes: row 1 = full-width **Buy Coffee**; row 2 = two columns **Send** and **Get**.

## Current State

- `apps/web/src/app/page.tsx` renders `<HomeDashboard />` when a session exists.
- `apps/web/src/components/home-dashboard.tsx` renders:
  - A top panel with "My address", copy button, and a "Balances" list of all assets (XLM + TAK).
  - A 2-column `grid grid-cols-2` of nav links: Buy Coffee, Send TAK, Get TAK, Profile, Admin Panel (admin conditional).
- `apps/web/src/components/nav-bar.tsx` is the hamburger menu (Home, Buy Coffee, Send TAK, Get TAK, Profile, Admin Panel, Log out). No Wallet entry.
- Balance data comes from `wallet.balance` (returns `{ asset: 'XLM' | 'TAK', stroops }[]`, see `apps/web/src/server/trpc/routers/wallet.ts` and `apps/web/src/server/stellar/horizon.ts`).
- `@takapp/shared/money` exposes `lumensFromStroops` for display.
- Existing pages: `/buy`, `/send`, `/tak`, `/profile`, `/admin`. No `/wallet`.
- SW precache is generated by `@serwist/next` from the build manifest, so a new route needs no extra offline config.

## Changes (ordered)

### 1. Rework `apps/web/src/components/home-dashboard.tsx`

- Drop `isAdmin` from the `useWallet()` destructuring (no longer used here).
- Derive the TAK entry: `const takBalance = balanceQuery.data?.balances.find((entry) => entry.asset === 'TAK');`.
- Top panel becomes, in order:
  1. "TAK balance" label (small `text-coffee-300`).
  2. Large TAK amount (`text-4xl`/`text-5xl font-bold text-coffee-100`) with a smaller "TAK" suffix. Use `lumensFromStroops(takBalance.stroops)` when present, else `'0'`. Keep the loading / error states (`balanceQuery.isLoading` / `balanceQuery.isError`).
  3. "Address" label + the public key `<code>` + the existing Copy button (unchanged behavior).
- Replace the `navLinks` array + single `grid grid-cols-2` section with:
  - Row 1: one full-width `Link` to `/buy` labeled "Buy Coffee".
  - Row 2: a `grid grid-cols-2 gap-3` with `Link` to `/send` labeled "Send" and `Link` to `/tak` labeled "Get".
- Remove the now-unused `Link`/`useState` imports only if they become unused (Link still used; `useState`/`copied` still used by Copy).

### 2. Create `apps/web/src/app/wallet/page.tsx`

- `'use client'`.
- Guard: if no `session`, render the standard "Please log in" + "Go to login" fallback (mirroring `tak/page.tsx`).
- Layout: `<main className="mx-auto flex min-h-screen max-w-md flex-col gap-6 p-6">`.
- Title `Wallet`.
- Balance panel (`rounded-xl bg-coffee-900 p-6 shadow`):
  - "Balances" label.
  - Loading / error / empty states mirroring the current home list.
  - Render every entry in `balanceQuery.data.balances` (XLM and TAK) in the existing `divide-y` list style with `lumensFromStroops`.
- Action row: `grid grid-cols-2 gap-3` with `Link` to `/tak` labeled "Get TAK" and `Link` to `/send` labeled "Send".

### 3. Add Wallet to `apps/web/src/components/nav-bar.tsx`

- Insert `{ href: '/wallet', label: 'Wallet' }` into the `links` array (after Home, before Buy Coffee).
- Keep Profile, Admin Panel, Send TAK, Get TAK entries as-is (these are the menu destinations referenced in requirement 3).

## Decisions / Notes

- **Wallet route path**: `/wallet`.
- **Home labels**: "Buy Coffee" (full width), "Send", "Get" — matching the requirement. Existing routes `/send` (Send TAK) and `/tak` (Get TAK) are reused; their page titles are unchanged.
- **Copy affordance** on the home address is preserved (no requirement to remove it).
- **No server/tRPC/DB changes**: balance data already returns both assets; filtering happens client-side.
- **`isAdmin`** remains used only in `nav-bar.tsx` (menu), which is the intended place for Admin going forward.

## Validation

- `pnpm typecheck` (covers unused-vars via `tsc` + TS strict).
- `pnpm lint`.
- `pnpm test` (no UI tests exist; server tests must stay green).
- Manual smoke via `pnpm build` then `pnpm dev`: log in, verify home shows TAK (large) + address only; grid shows Buy Coffee full-width then Send/Get; `/wallet` shows XLM + TAK + Get TAK/Send; menu includes Wallet and still shows Profile/Admin; admin badge behavior unchanged.

## Risks

- None material. Changes are confined to three client components plus one new page.
